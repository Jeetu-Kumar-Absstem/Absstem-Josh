Read-only audit

Josh UI/UX and ease-of-operations audit

This review is based on a read-only walkthrough of the main app shell, Home, Quotes, Manufacturing BOMs, Admin Desk, Tally Import, and SuperAdmin governance surfaces. No source code was changed.

Overall readout

The product direction is strong: queue-first work, guided flows, and role-led navigation are already visible. The main issue is not missing capability. It is operational density. Users are still being asked to solve too much master-data, approval, mailbox, and exception handling inside their primary transaction screens.

Primary strength Guided desks

Home, Quotes, and BOM already push users toward focused work instead of generic menu browsing.

Primary risk Workflow drag

Master-data gaps, approval routing, and admin fragmentation slow down completion even when the UI itself is improved.

Strong Autopilot direction High dependency on setup quality Approval and mailbox bottlenecks Best next step is no-code operational cleanup

What is working well

User navigation

Home is role-first

Home is clearly trying to behave like a working inbox instead of a dashboard wallpaper. “Do this next”, “Waiting on you”, and role-filtered desks are the right structural choices.

Sales flow

Quotes have a real guided path

The queue-first quote desk and the 4-step builder are aligned with real sales behavior. The app now favors guided creation first and detailed control only when needed.

Factory governance

BOM editing is controlled

The readiness states, lock states, inheritance rules, and revision model protect operational integrity. That is a solid base for scale.

Main bottlenecks

1

Master-data dependency inside transaction flows

Quotes and BOMs are faster only when customer, site, contact, product, spec, and company setup are already clean. Today, too much of that cleanup still lands on the person trying to finish a live transaction.

2

Approval paths as work blockers

The product exposes approvals clearly, but completion still depends on approver availability, threshold setup, and escalation readiness. That turns policy into queue drag.

3

Mail and delivery readiness

The quote journey is only truly complete when sender configuration is ready. Sales users should not discover mailbox problems at the last step.

4

Admin surface fragmentation

Operational admin, business admin, and superadmin capabilities are all present, but they are distributed across separate desks. The split is logical in code, but still expensive in mental overhead.

5

Search and refresh trust

Several admin and ops screens suggest search and filtering, but the operator experience can feel inconsistent when data refresh behavior is not tightly aligned to filter changes.

6

Knowledge bottlenecks

The product assumes users know which desk, owner, and escalation route handles a given blocker. That is manageable for power users, but slower for new or occasional operators.

Operator runbooks and role onboarding High Short term Training can remove a lot of friction without any product change.

No-code plan

Phase 1

Stabilize the operating model

  • Define ownership for every critical queue: pending approvals, issued-not-sent quotes, stale drafts, BOM setup gaps, and Tally review exceptions.
  • Create backup approver rules for quote and BOM approval workflows.
  • Assign named mailbox owners and fallback sender rules for quote delivery.
  • Publish a simple “which desk handles what” map by role family.
Phase 2

Remove setup friction from live work

  • Set a same-day SLA for urgent customer, site, contact, and product-master requests tied to active commercial work.
  • Run a recurring BOM readiness review for FG setup gaps, specs, and inherited BOM ownership.
  • Pre-create common customer contacts, sites, and frequently quoted configurations for top accounts.
  • Document standard commercial defaults so sellers know when they are safe to stay on the default path.
Phase 3

Professionalize admin operations

  • Separate operating responsibilities clearly: Admin Desk for live governance, SuperAdmin for setup and policy, Tally Import for controlled financial migration work.
  • Create short runbooks for audit review, role change, backup verification, Tally import, and variance escalation.
  • Introduce a fixed cadence: daily audit check, weekly backup verification, scheduled import windows, and monthly rights review.
  • Track unresolved admin exceptions in one owner-led queue instead of leaving them embedded across tools.
Phase 4

Measure friction before changing UI again

  • Measure time-to-first-quote, quote-to-send cycle time, approval turnaround time, and BOM activation turnaround.
  • Track how many live transactions are blocked by setup, approval, mailbox, or missing master-data.
  • Use pilot feedback to separate training problems from actual product problems.
  • Only after these numbers settle should the next UI/code round be prioritized.
